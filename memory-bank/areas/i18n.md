# Area: i18n

Localization: routing, message catalogs, and bundle scoping.

## Roots

- `src/i18n/routing.ts` — `routing` (locales `ka`/`en`/`ru`, default `ka`,
  `localePrefix: "as-needed"`, detection off) + `AppLocale` type.
- `src/i18n/request.ts` — `getRequestConfig`: dynamic `import(messages/${locale}.json)`.
- `src/i18n/navigation.ts` — locale-aware `Link`/`redirect`/`useRouter`/`getPathname`.
- `src/i18n/namespaces.ts` — `PUBLIC_NAMESPACES` allow-list + `pickMessages`.
- `messages/{ka,en,ru}.json` — the catalogs (ka is the largest / authoritative).
- `src/middleware.ts` — runs `intlMiddleware` first, then Supabase session for
  protected routes (bridges i18n ↔ auth).
- Guards: `scripts/i18n-scope.mjs` (`--check`, `prebuild`) and
  `scripts/check-message-parity.mjs`.

## Responsibilities

- Resolve the active locale per request and load only the needed messages.
- Keep the **public** hydration payload small: root provider ships only
  `PUBLIC_NAMESPACES`; dashboards ship the full bundle in a nested provider.

## Blast radius

- Adding a locale: `routing.locales` **and** a new `messages/<locale>.json`, or the
  dynamic import throws (**C2**).
- Adding user copy: key must land in **all three** catalogs (**C1**); if the string
  is used by a public client component, its namespace must be in
  `PUBLIC_NAMESPACES`.
- The middleware locale prefix-strip loop hard-codes the reduce over
  `routing.locales` — it stays correct only because it reads that list.

## Contracts touching this area

C1 (parity + scoping), C2 (locale set).
